# QuickRapidX

Десктопная утилита для Windows. Tauri 2 + SvelteKit 5 + TypeScript, пакетный менеджер — bun.

Оформление целиком перенесено из предыдущей версии приложения: те же стили, иконки,
шрифты и разметка. Изменены только механизмы, которые в прошлой сборке работали неверно.

## Запуск

```bash
bun install
bun run tauri dev     # разработка
bun run tauri build   # релизная сборка
bun run check         # проверка типов (svelte-check)
```

## Окна

Три окна объявлены в `src-tauri/tauri.conf.json`, все создаются скрытыми — показывает их
ядро. Размеры перенесены из предыдущей версии.

| Окно     | Маршрут    | Размер   | Роль                                       |
| -------- | ---------- | -------- | ------------------------------------------ |
| `splash` | `/splash/` | 350×450  | Экран загрузки, показывается первым        |
| `main`   | `/`        | 1280×730 | Главное окно, минимум 1280×730             |
| `tray`   | `/tray/`   | 390×490  | Панель у иконки в трее, поверх других окон |

Все три — без системной рамки. Фон, границу и скругление рисует `#app` из `app.html`,
как и раньше.

## Порядок загрузки

1. `setup()` показывает `splash` и строит иконку в трее.
2. Фронтенд, отрисовавшись, зовёт команду `boot_start` — так первые события прогресса
   не уходят в пустоту.
3. `src-tauri/src/boot.rs` в фоновом потоке проходит по шагам (каталоги → настройки →
   окружение → модули → интерфейс) и после каждого шлёт `boot:progress`.
4. По завершении — `boot:ready`: ядро показывает главное окно и закрывает заставку.
   Главное окно держит тот же экран загрузки ещё 1.4 с и открывает содержимое.
   Отсюда знакомая последовательность: маленький экран загрузки → большой → приложение.

Главный поток при этом не блокируется: в прошлой версии здесь стоял
`thread::sleep(5s)` прямо в `setup()`.

## Что изменено против оригинала (и почему)

| Было                                                          | Стало                                                        |
| ------------------------------------------------------------- | ------------------------------------------------------------ |
| Тема переключалась созданием `<link href="/src/lib/...css">`   | Оба набора правил в бандле, переключение через `data-theme`   |
| Путь `/src/...` существует только у dev-сервера                | В собранном приложении тема раньше не применялась вовсе       |
| `{#each LangGet as item, i}` вокруг всей страницы, `{#if i===0}` | Словарь отдаётся объектом, реактивность даёт руна            |
| `style.ts` с top-level await и 8 динамических import()          | Статические импорты в `+layout.svelte`                        |
| `create_dir_all("home/save/...")` от текущего каталога          | Каталоги в `app_data_dir()`                                   |
| `thread::sleep(5s)` в `setup()`                                 | Загрузка в фоновом потоке, события прогресса                  |
| `csp: null`, `assetProtocol` на `*/**`, fs-доступ к `$DESKTOP` | Точечный CSP и список прав под конкретные окна                |

## Структура

```
src/
  lib/
    App/              перенесённые ассеты: img, sound, style, fonts
    actions/          use:-директивы (клик вне элемента)
    components/       Preloader, Titlebar, Home, Notification, Console
    data/             переводы, шаблоны записей
    state/            загрузка, язык, тема, уведомления, рамка окна
  routes/
    +page.svelte      главное окно
    splash/           окно загрузки
    tray/             панель трея
src-tauri/src/
  lib.rs              сборка приложения, команды, события окон
  boot.rs             последовательность загрузки
  tray.rs             иконка в трее и позиционирование панели
  paths.rs            каталоги данных и config.json
```

Темы лежат рядом в двух видах: исходные `theme_black.css` / `theme_white.css` и
сгенерированные из них `scoped_dark.css` / `scoped_light.css` — содержимое правил
не менялось, добавлен только префикс селектора.

## Что осталось перенести

Остался вспомогательный компонент `HorizontalScroll`. Всё остальное — и фронтенд,
и ядро — перенесено.

Экраны, которых ещё нет, помечены в интерфейсе и не притворяются рабочими: вызовы
недостающих команд перехватываются и пишут предупреждение в консоль.

### Замечания по перенесённому системному слою

`windows_shutdown`, `windows_restart` и `windows_logoff` вызывают `shutdown.exe`
вместо `ExitWindowsEx` с ручной выдачей привилегии `SE_SHUTDOWN` — так же, как это
уже делал `windows_logoff` в оригинале. Поведение то же, кода без `unsafe` заметно
меньше.

`regedit_set_keys_hibernate` теперь проверяет код возврата `powercfg`: без прав
администратора команда завершается ошибкой, и раньше это молча считалось успехом —
флажок вставал в новое положение, хотя гибернация не менялась.

Настройки корзины (`basket.rs`) перебирают тома в
`...\Explorer\BitBucket\Volume`, а не берут единственный зашитый GUID
`{6ffcef13-4d28-44af-991e-251460b61a48}`. Этот идентификатор относится к тому
конкретной машины: на любой другой ключа с таким именем нет, и лимит корзины,
режим удаления и их запись отваливались с ошибкой открытия ключа. Запись идёт
во все тома, чтение — из первого, где значение нашлось.

`editor_person_in_json` больше не пишет в поле `id` номер строки. Раньше
`person.id = linene_id.to_string()` затирал идентификатор записи при первом же
редактировании.

Файл `app_data.json` переехал из относительного `home/save/app/` в
`app_data_dir()/apps/`. Повреждённый файл уводится в `app_data.broken.json`,
а вкладка открывается с пустыми списками вместо ошибки разбора.

Поиск установленных программ (`app_search.rs`) берёт каталоги из переменных
окружения `ProgramFiles`, `ProgramFiles(x86)`, `LOCALAPPDATA` и `APPDATA`.
Раньше пути собирались как `C:\Users\{username}\AppData\...` через crate
`whoami` — на машине, где Windows стоит не на диске C или профиль лежит в
другом месте, поиск не находил ничего. Недоступный каталог теперь пропускается,
а не обрывает весь поиск ошибкой; дубли по имени убираются; обход файловой
системы идёт в блокирующем потоке, чтобы не морозить интерфейс.

Форма создания записи не дублирует разметку редактора: в исходном приложении
`CreateYourEntry` и `AppStatsInfoEditor` содержали одну и ту же вёрстку из
шести полей. Здесь это один компонент с разными обработчиками сохранения.

Музыка мастера первого запуска подключается импортом, а не адресом
`/src/lib/App/sound/create_settings/sound_1_320.mp3`. Такой путь существует
только у dev-сервера — в собранном приложении звук не игрался, как и темы.

Панель трея позиционируется по прямоугольнику иконки из события клика (`rect`),
а не по курсору и не по рабочей области монитора. Курсор в момент клика
находится внутри панели задач, а `Monitor::work_area()` её не исключает, если
панель задач скрывается автоматически: замер на реальной машине дал рабочую
область `0,24..1920,1080` при экране `1920×1080` — то есть снизу не
зарезервировано ничего. Прямоугольник иконки верен в обоих случаях и заодно
говорит, у какого края экрана стоит панель задач. Монитор берётся тот, над
которым курсор, — иконка может быть и на втором экране.

Размер панели считается как логический размер из конфигурации, умноженный на
масштаб монитора, а не берётся из `outer_size()`: скрытое окно, которое ещё ни
разу не показывали, может вернуть логический размер вместо физического, и на
экране с масштабом 125/150 % позиция уехала бы вниз.

### Открытие и закрытие панели трея

Клик по иконке сначала уводит фокус с открытой панели — она прячется по
`WindowEvent::Focused(false)` — и только потом до приложения доходит само
событие клика. Обработчик видел «панель скрыта» и открывал её заново: закрыть
панель кликом по иконке было невозможно, она мигала и оставалась на экране.

Момент такого автоскрытия отмечается, и клик, пришедший в ближайшие 300 мс,
считается тем же самым — панель остаётся закрытой. Отметка ставится только
когда курсор находится над иконкой (`TrayIconEvent::Enter` / `Leave`): если
пользователь щёлкнул мимо, панель просто закрылась, и следующий клик по иконке
должен открыть её сразу.

Левый клик прячет главное окно, только когда оно действительно активно. Окно,
которое видно, но лежит под другими, клик поднимает наверх — раньше оно
пряталось в ответ на попытку его открыть.

Плагин `single-instance` подключается всегда, в любой сборке. Подключать его по
условию нельзя в принципе: защиту заводит **первый** процесс — он создаёт
общесистемный мьютекс и скрытое окно, а поздние по ним и узнают, что копия уже
есть. Если у работающего экземпляра плагина нет, узнавать не по чему, и второй
запуск честно поднимает вторую копию.

Раньше он подключался только в релизе — из опасения, что `tauri dev` отдаст
запуск висящему экземпляру и молча выйдет. На ярлыках наборов это и вылезло:
ярлык поднимал вторую копию приложения вместо панели. Поведение приложения не
должно различаться между сборками, иначе такие ошибки всплывают у пользователя,
а не на сборке.

### Состояние загрузки опрашивается, а не только рассылается

События Tauri уходят один раз и не повторяются: окно, чей интерфейс ещё не
подписался, ничего не получит. Главное окно грузит весь CSS приложения и вполне
может не успеть за время загрузки ядра — тогда оно ждало бы `boot:ready`,
которого уже не будет, и висело бы на экране загрузки бесконечно.

Поэтому ядро держит флаг `DONE` и отдаёт его командой `boot_status`: окно
подписывается на события и сразу же спрашивает состояние. Плюс `boot_start`
зовётся из обоих окон — защита от повторного запуска в ядре делает второй
вызов безвредным, зато отказ окна-заставки больше не оставляет приложение
висеть.

## Оформление

### Токены вместо вписанных цветов

Цвета были вписаны в правила по месту: одно золото встречалось 34 раза. Тема
переключалась двумя файлами, которые на 83 % состояли из подмены файлов иконок,
а остальное дублировало те же правила с другими значениями.

Теперь `main/tokens.css` держит значения, а правила оформления одни на обе темы.
Цвета с переменной прозрачностью берут тройку компонентов —
`rgb(var(--gold-rgb) / 0.5)`, — чтобы значение оставалось одно.

### Иконки — маска вместо второго файла

Рядом с каждой иконкой лежала чёрная копия, и тема переключалась подменой
`background-image`. Маска берёт из файла только форму, цвет задаётся стилем:

* 60 иконок стали масками с цветом из токена;
* 6 цветных значков разделов остались картинками — они одинаковы в обеих темах;
* 2 многоцветные (`ST-T`, `download_ico`) остались с подменой по теме: в них
  золото соседствует с белым, и одной маской их не покрасить.

Файлов иконок стало 90 вместо 147. У девяти элементов маска вынесена на
псевдоэлемент `::before` — у них есть собственный фон-подсветка при наведении,
и маска на самом элементе обрезала бы его по форме иконки.

### Размеры в пикселях вместо долей окна

`1vw` — сотая доля ширины окна, поэтому при другом размере окна вся вёрстка
съезжала: шрифт в `1.1vw` на экране 1920 превращался в 21px. Отсюда и жёстко
заданный размер главного окна.

429 значений из 505 переведены в пиксели по размеру того окна, для которого
правило написано: главное — 1280×730, трея — 390×490. При исходном размере вид
не изменился, но теперь он не зависит от размера окна.

Оставшиеся 66 намеренно относительные:

| Где | Сколько | Почему |
| --- | ---: | --- |
| мастер первого запуска | 57 | окно на нём разворачивается на весь экран |
| `load.css` | 5 | экран загрузки показывается и в заставке 350×450, и в главном окне |
| `main.css` | 3 | правила для элементов вообще, общие для всех трёх окон |
| `media.css` | 1 | внутри медиазапроса |

## Производительность

### Универсальный переход снят

В исходном оформлении стояло `* { transition: all 0.5s }`, а также по такому же
переходу на `html`, `body`, `p`, `a`, `img` и `::-webkit-scrollbar`. Это значит,
что любое изменение стиля у любого элемента запускало полусекундную анимацию
всех свойств — включая размеры, отступы и положение, то есть с пересчётом
раскладки на каждом кадре.

Вместо `all` перечислены свойства, которые считаются без пересчёта раскладки:
`background-color`, `border-color`, `border-radius`, `color`, `opacity`,
`box-shadow`, `transform`. Все 36 правил `:hover` из оформления в этот список
укладываются, кроме одного: кнопка «+» во вкладке «Приложения» меняет при
наведении размер и кегль — ей переход выписан отдельно.

Оттуда же убран `image-rendering: crisp-edges` с `*` и `html`: он отключает
сглаживание при масштабировании и нужен разве что пиксель-арту, а фотографии
от него выглядят рвано.

### Анимация сворачивания окна

Окно создаётся без системной рамки, а Windows решает, проигрывать ли анимацию
сворачивания, по стилю окна: без `WS_CAPTION` и `WS_MINIMIZEBOX` оно просто
исчезает и появляется рывком. `window_fx.rs` возвращает эти биты стиля напрямую;
рамка при этом не появляется, потому что перерисовку рамки
(`SWP_FRAMECHANGED`) мы не запрашиваем — меняется только поведение.

Анимация работает при сворачивании любым способом: кнопкой в заголовке, кликом
по значку на панели задач, `Win+D`. Поверх системной анимации содержимое окна
плавно проявляется при возврате (`window-fx.css`) — анимируются только `opacity`
и `transform`, их браузер считает на композиторе.
